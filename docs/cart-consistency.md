# 购物车同步与结算

前后端需要同时更新。服务启动时会迁移购物车重复行、建立用户/商品/规格唯一索引，并创建 `shop_cart_states` 与 `shop_checkout_requests`。重复旧行保留最大数量，不累加购买数量。

## 接口

- `GET /api/cart`：登录用户的 `{ version, items }`，包含当前单价、库存、规格和失效原因。
- `PUT /api/cart`：提交 `{ version, items: [{ productId, skuId, quantity }] }`。版本必须匹配，成功后版本加一；旧版本返回 409。最多 100 行，每行数量为 1–999 的整数。不接受重复行、错误规格归属或新增失效商品。已存在的失效行允许保留、减少或删除。
- `POST /api/cart/preview`：公开的只读接口，提交商品 ID、规格 ID 和数量数组，刷新游客购物车信息，不保存数据。
- `POST /api/cart/checkout`：登录用户提交固定的 `requestId`、`version`、`addressId`、`userCouponId`、`expectedAmount` 和含单价的 `items`。服务端重新校验金额、库存、优惠券及地址归属。在同一事务中创建订单、扣除实际购买数量、更新购物车版本并记录请求回执。

相同用户、相同请求 ID 和内容重试会返回原订单；同 ID 不同内容返回 409。金额或商品价格变化也返回 409，页面刷新后需要重新确认。此流程保持原有“支付时扣减库存”的规则。

## 本地状态

购物车缓存按用户名隔离，游客使用独立键。只合并新格式的游客购物车，成功写入后移除已合并的游客商品。勾选状态保存在本地，不触发服务端全量覆盖。

旧缓存带有已登录账号信息时会迁移并重建商品/规格键。无法确认归属的旧缓存保留在 `shop_cart:legacy-unassigned`，不会自动导入下一个登录账号。

写入请求串行执行，过程中发生的修改进入下一次同步。版本冲突时加载服务端最新内容并提示重新操作，避免用本地快照覆盖其他设备的修改。网络失败保留本地修改，可点击提示重试，恢复联网时也会尝试刷新。

提交订单前将完整请求持久化。网络或服务端异常导致结果不明时，冻结购物车编辑并保留请求，刷新页面后仍可用同一请求重试；已明确拒绝的请求才会解除冻结。成功后直接使用事务返回的购物车，不再另外发送清空请求。

## 验证

在项目根目录运行 `go test ./...`；在 `frontend` 目录运行 `npm test` 和 `npm run build`。

回归测试覆盖账号隔离、迟到响应、连续数量编辑、断网重试、版本冲突、失效商品、旧数据迁移、组件输入、结算响应丢失、重复请求及事务失败回滚。默认后端测试使用 SQLite；可显式启用下述真实 MySQL 集成测试。

## 独立执行 MySQL 迁移

应用运行时已经使用 MySQL。以下命令复用现有 `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_USER`、`MYSQL_PASSWORD` 和 `MYSQL_DATABASE` 配置，不启动应用，也不执行订单、金额或种子数据的其他迁移。

```powershell
# 只读检查连接、表、行数、唯一索引及重复数据
go run ./cmd/cart-migrate

# 执行可重复的购物车迁移，然后输出检查结果
go run ./cmd/cart-migrate -apply
```

迁移命令使用 MySQL 命名锁防止两个迁移进程同时执行；现有购物车非空时，先在同库创建 `shop_cart_backup_<时间戳>` 备份表。该锁不阻止正常业务写入，因此有业务流量时应在维护窗口执行迁移。

真实 MySQL 集成测试在同一服务器创建名称以 `shop_cart_verify_` 开头的独立临时库，结束后自动删除；应用库不参与测试。运行账户需要创建、删除临时库的权限。

```powershell
$env:SHOP_MYSQL_INTEGRATION = '1'
go test ./internal/api -run '^TestMySQLCart' -count=1 -v
```

已在 MySQL 8.4.10 验证旧行去重、空规格迁移、重复迁移、唯一索引、版本冲突、账号隔离、并发重复结算和事务回滚。
