# 订单、售后、物流与客服

本次补齐整单售后、支付宝退款和关单、商家发货、站内客服咨询，以及商品规格编辑与购买校验。

## 买家操作

- 订单列表或详情中的「申请售后」填写原因，选择仅退款或退货退款。未发货订单仅支持退款。
- 商家同意退货后，订单详情会显示退货地址。寄出商品后填写快递公司、运单号，等待商家验收退款。
- 订单详情显示快递公司、单号及商家录入的物流进度。
- 「我的 → 客服与帮助」直接发送问题，默认由自动客服解答订单、付款、物流、售后、地址、优惠券和商品规格等常见问题。未知问题会说明未找到答案，并提示转人工。
- 只有明确发送「联系人工」（或点击同名按钮发送该消息）才会转入人工客服队列。提问中仅提到人工不会触发转接；转接后停止自动回答，保留此前聊天记录。人工回复会生成站内通知，打开的对话每 5 秒刷新。
- 多规格商品必须选择有效规格，售罄规格不可选；「立即购买」选中当前商品并进入结算。

## 后台操作

- 「订单 → 详情 / 处理」可以查看商品规格和收货地址。
- 待发货订单填写快递公司、运单号后确认发货。已发货订单可补充真实物流进度。
- 售后申请可以驳回（须说明原因）、同意退货（须提供退货地址）或确认整单原路退款。
- 退货退款必须经过同意退货及买家提交运单；商家验收后操作退款。只有勾选「可售商品退回库存」的退货才回库。未发货订单退款自动恢复原扣库存；已发货且无需退回的退款不回库。
- 退款超时或网络异常会保留「退款确认中」，可使用「重试确认退款」。每单使用固定退款请求号；确认成功后，库存、销量和优惠券只恢复一次。
- 后台无法通过任意改状态伪造付款、发货或退款。
- 新增「客服管理」及 `support:manage` 权限。管理员角色在启动时自动获得该权限，其他员工角色需要按需分配。
- 客服后台默认仅显示已请求人工的咨询，可筛选等待人工、人工服务中、自动应答和全部咨询。自动应答会话只能查看，服务端同样禁止人工提前回复或结束该会话。人工首次回复后进入「人工服务中」。升级前已有咨询继续作为人工会话处理。
- 商品规格支持编辑价格和库存。下架商品的规格也可维护。

## 支付与升级

- 使用现有支付宝配置，退款和关单调用 `alipay.trade.refund`、`alipay.trade.close`。
- 未付款订单在创建 30 分钟后过期，后台每 30 秒分批补查支付结果并检查过期订单。关闭收银台后仍会补查已发起的支付。主动取消时先关闭支付交易；关单失败时保留订单并尝试查询付款结果。
- 取消后收到付款回调的订单转为待审核退款，保留交易号和金额；不丢弃已到账款项，也不扣库存。
- 支付落库、库存扣减、优惠券核销和销量更新使用数据库事务。库存或优惠券不可用时保留支付信息并转售后，等待商家原路退款。
- 应用启动时自动迁移新增字段、客服表和权限。订单历史字段迁移使用事务及版本标记，可重启重试。
- 历史售后订单缺少可靠的库存扣减记录，迁移后可核实交易并退款，但不会自动恢复库存，需人工核实后调整。历史待付款订单保守视为可能已生成支付交易，需要支付服务关闭交易。

## 当前边界与验收

- 售后支持整单全额退款；部分退款、换货和图片举证不在本次范围内。
- 物流进度由商家录入，尚未连接快递公司的自动轨迹接口。
- 自动客服使用内置常见问题规则，不调用外部大模型，也不会推测实际订单、退款结果或送达时间；未匹配时提示继续提问或发送「联系人工」。人工客服为站内咨询及回复，未连接第三方客服平台或电话服务。
- 已运行后端自动化测试及前端生产构建。支付测试使用替身，尚未执行真实支付宝扣款或退款；上线前需用自己的沙箱或商户配置验证关单、付款回调及退款。
- 后端回归包含退款超时重试、退货流程、不退货退款、取消后迟到付款、支付事务回滚、历史数据迁移、用户数据隔离、客服回复通知及规格校验。
